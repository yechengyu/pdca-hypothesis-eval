# 自我优化 + 校准计划

> 状态：设计稿。骨架阶段先把评估跑通；本闭环待校准信号累积后实现。

## 目标

让 `rubric/pdca_rubric.json`（评估假设的标尺）持续进化，使 AI 按它打出的评估
**越来越接近资深评审者的判断**。人的判断是金标准，rubric 是被优化的对象。

## 校准信号怎么来：增量反馈，非批量打分

不要求评审者预先批量给一堆假设打分。改成**用起来攒**：每次 skill 评完一条假设，
评审者随手补一句「评得对 / 需校准+怎么改」，由 `scripts/log_feedback.py` 记进
`references/calibration_feedback.jsonl`（本地文件，不随 skill 分发）。一条条累积成金标准库。

- `verdict=ok` → 这次 AI 评得对，是正样本（当前 rubric 在这条上没问题）。
- `verdict=recalibrate` + `comment` → AI 评偏了，comment 是人对"该怎么评"的修正
  （如"检验时点你给松了应是 0 分"）。这是最值钱的信号，直接指向 rubric 哪里要改。

起步只要三四条即可。低质量的历史假设适合补低分段样本，但不能只靠它，
需随真实使用补齐中高质量样本。

## 什么时候触发优化（cadence）

**不按固定时钟。** 使用量低时定时跑大多是空跑，且单条纠偏改 rubric 容易过拟合
（一条教训不一定适用别的指标类型，要看几条同类才知道规则普适）。

改成**按信号量触发**：

- **够量才改**：自上次优化以来攒满 **≥5 条新校准信号**（尤其 `recalibrate`）才做一次优化 pass。
  5 条才能分清"反复出现的同类问题"（值得改 rubric）和"一次性意外"（不该改）。
- 跑 `python3 scripts/calibration_status.py` 看够没够；够了就改，不够就等。
- 优化做完，用 `scripts/calibration_status.py --mark-optimized` 记基线，下次从这之后重新数。

## 优化机制（爬山 + 盲评门控）

1. **打分差距 = 适应度**：拿累积的校准库当标准答案，当前 rubric 让模型对这些假设打分，
   与人的修正算差距（recalibrate 条目是否还会再被标 recalibrate / 维度命中率）。差距越小越好。
2. **爬山迭代**：每轮让一个 proposer 读"哪些假设 AI 和人分歧最大 + 为什么"，
   提出对 rubric 的小改（调权重 / 改打分细则措辞 / 增删维度）。
3. **盲评门控**：独立 judge 在不知道哪版是新旧的前提下，比较改前/改后 rubric 在
   **留出集**（held-out，不参与提议的那部分）上的打分差距，只有真的缩小才采纳。
4. **git 版本化 + 收益递减自动停**：每版 rubric 提交一次；连续两轮无显著改善则停。
5. **人在闭环**：每次采纳新 rubric 前给评审者看 diff，他点头才合并（不自动改）。

## 多模型（可选）在优化里的角色

若使用方配了多个大模型的 key，三家按同一 rubric 打分的**一致性**是 rubric 质量的旁证：
一条写得清楚的假设各家应趋同；若某维度长期发散，说明该维度打分细则本身含糊，
是优化的优先目标。没配 key 时跳过这层，不影响主流程。
